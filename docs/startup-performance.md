# 首屏加载与性能验收

## 加载约束

- 普通页面不等待安装状态。只有接口明确返回 `requiresSetup: true`、认证初始化完成且用户为空时，才进入 `/setup`。安装状态失败只记录日志。
- 首页活动、曲目、专辑和图集独立提交结果。重试只更新对应区域的请求版本；卸载和 StrictMode Effect 重启会使旧版本结果失效。继续使用 `apiGet` 的去重与 SWR 缓存。
- 登录弹窗在入口可见或有操作意图时准备代码，首次打开才挂载，之后保留组件挂载条件以支持关闭动画。公告有可见数据时才加载动画组件；关闭、持久化关闭和定期刷新保持原有行为。
- 启动占位在 React 首次提交后的 Effect 中退出，不等待首页 API。HTML 清理函数幂等，并保留淡出过渡与八秒超时。
- React、图标、动画和大型可视化库保留显式分包，其余依赖按使用方自动拆分。不要把所有第三方库重新合并进首屏通用 vendor 包。
- 全站路由和按需功能共用模块缓存及同步热打开入口。主要编辑操作在主体就绪后空闲准备，普通链接接近视口时准备，聚焦、触屏按下和持续悬停提升优先级。仅准备代码与 CSS，不提前挂载组件或请求业务数据。
- 推测任务串行执行，队列最多四个模块；每个路由及身份作用域自动启动最多两个模块，明确操作意图可替换低优先级排队任务且不受自动预算限制。路由或身份变化取消排队，离线、后台、省流量和极弱网不启动新任务；正常导航绕过推测调度。

## Service Worker

缓存版本为 `v32.1`。

| 资源                                                       | 策略                         |
| ---------------------------------------------------------- | ---------------------------- |
| 同源 `/assets/` 下符合哈希文件名模式的 JS、CSS、字体及图片 | Cache First                  |
| HTML、SPA 导航                                             | Network First，在线重新验证  |
| `/api/`、带 Authorization 的请求                           | 不写入静态缓存，直接请求网络 |
| 上传文件和其他无哈希静态文件                               | Network First                |

静态资源只缓存成功的同源非 HTML 响应；离线首页壳只缓存成功的同源首页 HTML，并移除服务端注入的认证 UID。两者均排除 `private` 和 `no-store` 响应；不缓存受保护路由的 HTML。第三方资源不经过本站 Worker。

新 Worker 不调用 `skipWaiting()` 或抢占旧页面，等待旧页面退出后才激活；激活时只清理本站版本化缓存，不删除其他应用的缓存。这使正在运行的旧页面仍能访问已缓存的旧 Chunk。服务端也应保留仍可能被旧页面按需请求的哈希产物：Worker 无法恢复从未缓存、且已从服务器删除的文件。

## 可重复采样

使用 Node.js 22 和生产构建，不能用 Vite 开发服务代替。测试数据库与生产库隔离，先在 `/setup` 完成初始化并退出登录，保持无可见公告。采样前后使用相同数据库和内容。

```bash
npm ci
npx playwright install chromium
ANALYZE=true npm run build

# 配置独立测试数据库的 DATABASE_URL 后启动生产服务。
NODE_ENV=production PORT=3107 npm run dev

# 在另一终端采样，输出每次访问的完整指标及中位数。
npm run measure:startup -- http://127.0.0.1:3107/ /tmp/startup-after.json
```

对修改前保留的生产构建运行相同命令，写入独立的 `startup-before.json`。`BROWSER_EXECUTABLE_PATH` 可指定已有 Chromium；不设置时使用 Playwright 安装的浏览器。

固定条件：

- 移动端视口 390 × 844，device scale factor 为 1。
- Slow 4G 参数：延迟 150 ms，下行 `1.6 × 1024² / 8` B/s，上行 `750 × 1024 / 8` B/s。
- 页面 CPU 四倍降速；页面与 Service Worker 请求均应用相同网络限速。
- 每组五次全新浏览器上下文，每次首次访问后在同一上下文重复访问，共十个样本。
- 浏览器缓存冷热与数据库缓存冷热分开：不人为清空后端缓存。
- 复用 `src/utils/webVitals.ts` 的采集器，并持续观察最终 LCP。不能把启动占位的首个 LCP 或 React 提交时间当成最终页面 LCP。
- JavaScript 传输量由 CDP 汇总页面与 Worker 的实际网络传输，包含响应头；排除缓存交付的重复事件。页面脚本数量来自 Resource Timing，不把 Worker 注册更新检查计为页面脚本。

## 实测结果

以下为首屏优化的历史采样，不包含全站智能预加载后的浏览器耗时与流量测量。

环境：Node.js 22.23.4、Chromium 156.0.8078.4、本机 Express 生产服务、独立 PostgreSQL 测试库。数据库只有初始化用户，首页四个内容列表为空；以下数据不代表公网部署或真实图片内容的 LCP。修改前后分别使用保留的原始构建与优化构建。

原始样本包含每个 JS 文件及 API 的耗时、传输量、最终 LCP 元素和 Worker 控制状态：

- [优化前样本](performance/startup-before.json)
- [优化后样本](performance/startup-after.json)

所有时间取五次采样的中位数：

| 访问 | 指标                |   优化前 |   优化后 |
| ---- | ------------------- | -------: | -------: |
| 首次 | TTFB                |   5.0 ms |   3.3 ms |
| 首次 | HTML 响应完成       | 184.0 ms | 182.4 ms |
| 首次 | FCP                 |  1096 ms |   872 ms |
| 首次 | 首页标题 DOM 就绪   |  3731 ms |  1898 ms |
| 首次 | 最终 LCP            |  5512 ms |  3692 ms |
| 首次 | JavaScript 实际传输 | 510899 B | 205408 B |
| 首次 | 页面脚本数量        |       11 |        9 |
| 重复 | TTFB                | 166.2 ms | 164.8 ms |
| 重复 | HTML 响应完成       | 189.2 ms | 189.4 ms |
| 重复 | FCP                 |   380 ms |   252 ms |
| 重复 | 首页标题 DOM 就绪   |   725 ms |   640 ms |
| 重复 | 最终 LCP            |  2452 ms |  2408 ms |
| 重复 | JavaScript 实际传输 |    777 B |    777 B |
| 重复 | 页面脚本数量        |       11 |        9 |

重复访问的 JS 网络传输来自无哈希的 `/third-party-loader.js` 重新验证；哈希 JS 使用缓存。安装状态和认证请求的排队时序会变化，不应把页面提前显示解释成接口本身更快。

首次访问时首页 API 的端到端响应耗时如下，包含固定网络限速：

| API              |   优化前 |   优化后 |
| ---------------- | -------: | -------: |
| `/api/events`    | 159.5 ms | 158.5 ms |
| `/api/music`     | 171.2 ms | 166.8 ms |
| `/api/albums`    | 177.3 ms | 177.1 ms |
| `/api/galleries` | 165.2 ms | 163.3 ms |

构建分析确认，通用 vendor 包原先包含 Markdown、拖拽和图表底层依赖，gzip 体积约 313.5 kB。自动拆分后，这些页面专用依赖不再进入首页初始请求。无公告、未打开登录弹窗的真实浏览器验收也确认没有请求登录弹窗、登录表单、公告动画或 `vendor-motion` 专用 Chunk。

最终 LCP 元素为 `#home-title`，并非图片。Chrome DevTools trace 与样式共同定位到首页渲染及现有入场动画：标题动画为 1.2 秒，另有 0.35 秒延迟，父容器也有入场动画。本次保留页面设计与动画，不为压低指标提前移除效果。首次访问 LCP 尚未达到 2.5 秒目标；本机 TTFB 与 API 数据也不支持继续重构后端查询。

## 行为验收

组件测试通过本地真实 HTTP 服务驱动真实组件与 `apiClient`，覆盖安装与认证并发、区域独立提交、失败重试隔离、StrictMode、卸载旧结果、登录开关与公告持久化。没有 Mock 项目内部模块。

浏览器测试需要上述已初始化、无可见公告的生产测试服务：

```bash
STARTUP_BASE_URL=http://127.0.0.1:3107 npm run test:browser
```

浏览器验收覆盖专用 Chunk 按需加载、动态导入失败恢复、React 提交与启动占位衔接、入口失败的超时退出，以及真实 Cache Storage 的命中、私有响应隔离、离线导航和 Worker 版本交接。可见公告另以独立测试库中的真实公告验证动画加载、关闭与持久化。
