# 查找资源

## 来源优先级

1. 每次添加歌曲时，默认分别查询网易云音乐、QQ 音乐、酷狗音乐，将核实为同一作品、同一版本的所有可用来源添加到同一站内歌曲；找到一个平台来源后仍须继续查询另外两个平台。
2. 三大平台均无对应作品、版本的可用来源时，再考虑酷我音乐、5sing 等其他来源。
3. 不为凑齐来源关联同名翻唱、不同版本或未经核实的链接；缺少的平台来源如实说明。

按具体版本核对歌手、作品名称、词曲编、发行日期、曲目顺序和平台链接。区分原版、翻唱、现场、念白版、专辑版和伴奏，不因同名自动合并。专辑分碟及排序以可靠资料或用户指定为准。平台资料不一致时列出差异，不能确认的字段留空，不推测。

## 新歌查漏与 Meting 检索

- 查漏时分页读取全部站内歌曲，结合标题、艺人、版本及 `sources` 核对，不只看列表首页。`GET /api/music` 的 `sortOrder=desc` 按发行日期排列，不能据此判断最近入库时间。
- 可直接使用项目已有的 `@meting/core` 查询外部平台，无需浏览器。`new Meting('netease')` 或 `new Meting('tencent')` 后调用 `search(keyword, { type, page, limit })`；搜索类型为歌曲 `1`、专辑 `10`、歌手 `100`。
- 搜索歌手或专辑时使用 `format(false)` 并解析原始 JSON，避免歌曲格式化器不适用这些响应。网易云歌曲通常在 `result.songs`，专辑在 `result.albums`，歌手在 `result.artists`；QQ 音乐歌曲通常在 `data.song.list`，歌曲标识使用 `songmid`。
- 用歌手名加歌名搜索后，逐项确认返回艺人；同名翻唱或合集上传不能作为原唱来源。某平台未检索到原唱不等于作品不存在，应按来源优先级继续查询。
- 可用歌手官方发布或 Apple Music 发行页交叉核对最新作品及首发日期。单曲首发日期与影视原声带收录日期可能不同，应记录所选来源对应的日期，并在交付时说明差异。
- 查漏结论限定于实际核实范围；确认一首遗漏，不代表已穷尽所有合作曲、现场版本和伴奏。

## 歌曲描述

- 补全歌曲描述时，同时查看对应版本的平台歌曲介绍和所属专辑介绍；歌曲页没有介绍不代表没有可用描述。
- 确认为单曲专辑时，直接采用专辑介绍作为歌曲描述；同一单曲附带伴奏的发行也需核对曲目与版本。已有歌曲介绍时合并互补内容，避免重复。
- 多曲专辑只摘取明确介绍目标歌曲的段落，不把整张专辑的通用介绍套给每首歌；不能确定归属的内容不写入。
- 保留平台原文的有效内容与段落，不编造评价或背景；清除网页标签等展示残留，记录来源链接以便核对。已有描述先比较，仅补充缺失内容，不覆盖已核实的独有信息。
- 导入的 `fill` 不会补全 `description`；核实后用 `PATCH /api/music/:docId` 单独提交 `description`，不附带无关字段，写入后回读详情核验。

## 图片复用

- 获取或添加封面等图片前，先检查站内相关歌曲、专辑和图片映射，确认是否已有相同画面及版本。相同画面即使分辨率、格式、压缩或文件哈希不同，也应优先复用站内已有图片；不要重复上传外部版本。
- 判断是否相同时，核对图片内容和适用的作品、版本；不能只依据文件名、标题或哈希。哈希可用于确认字节完全相同，但哈希不同不代表画面不同。
- 优先通过站点图片映射和媒体资源复用接口取得可用资源，再关联到目标；已有专辑封面适用时，可使用专辑封面同步接口。遵守资源归属与权限，不通过绕过权限的方式复用。
- 未找到合适的站内图片时，按来源优先级查找对应版本的图片，核对后再上传。不得以不相关的封面或默认头像冒充作品封面。

## 操作与核验

- 操作网站前阅读 `public/api-docs.md`，先查询现有条目和来源，避免重复创建；涉及用户确认的内容，确认后再写入。
- API 密钥从用户指定的安全位置读取，不输出到聊天、日志、URL 或仓库。
- 用户指定 `API_KEY` 时，先检查环境变量；未设置再检查项目 `.env` 中的同名键。仅在进程内读取，通过 `Authorization: Bearer` 发送到已确认的网站域名，不打印环境文件内容或密钥。
- 新歌优先走平台导入：先调用 `POST /api/music/parse-url` 核对 `resource.songs` 的艺人、来源、版本与匹配状态，再调用 `POST /api/music/import`，显式提供目标 `selectedSongIds`，避免误导入整个专辑或歌单。只新增时使用 `duplicateStrategy: 'skip'`，补全已有条目才使用 `fill`。
- 导入后检查 `summary.imported/skipped/failed` 和结果列表，不能只看 HTTP 成功。单曲导入不会创建专辑实体；歌曲的 `album` 文本不等于已有专辑关联，应通过详情中的 `linkedAlbums` 核实。
- 保存歌词时移除 `[by:...]` 这类歌词文件制作者署名标签，保留歌词正文、时间轴及真实词曲编演职员信息；导入后同样检查并清理。
- 写入后读取目标详情，核对作品、版本、来源、封面及关联结果；说明已核实的内容和仍缺失的信息。
